# Olist dbt + Power BI

This project loads the original Olist CSV files into PostgreSQL, transforms them with dbt, and refreshes the existing Power BI report.

## Local setup

1. Start the dedicated local PostgreSQL container:

   ```powershell
   docker start olist_pg_local
   ```

   It is exposed at `localhost:5434` and uses the `olist_dw` database. Do not use port 5433; it belongs to another local project.

2. Activate the virtual environment:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

3. To reload the source data, run:

   ```powershell
   python .\python\load_data.py
   ```

4. Load the local environment variables and build the warehouse:

   ```powershell
   Get-Content .env | Where-Object { $_ -and -not $_.StartsWith('#') } | ForEach-Object {
     $parts = $_ -split '=', 2
     Set-Item -Path "Env:$($parts[0])" -Value $parts[1]
   }
   dbt run --project-dir .\olist_dw --profiles-dir .\olist_dw
   dbt test --project-dir .\olist_dw --profiles-dir .\olist_dw
   ```

## Power BI

Open `power bi/olist dashboard.pbix` in Power BI Desktop. In **File > Options and settings > Data source settings**, edit the PostgreSQL source to use:

- Server: `localhost:5434`
- Database: `olist_dw`
- Username/password: the `POSTGRES_USER` and `POSTGRES_PASSWORD` values in your local `.env`

The report expects the `dev` schema and these imported tables: `dim_customers`, `dim_geolocation`, `dim_product`, `dim_seller`, `fact_order_items`, and `fact_orders`. After updating credentials, choose **Refresh**. The PBIX itself is intentionally not modified.

The PBIP version in `power bi/pbip/` is the maintained report. It also imports `customer_summary`, `customer_rfm`, `customer_cohort_retention`, `seller_scorecard`, `region_summary`, `freight_demand_elasticity`, and `freight_subsidy_breakeven`, and connects to `localhost:5434`. Its five pages (Executive Summary, Revenue & Growth, Customers & Retention, Delivery & Customer Experience, Seller Performance) are generated by `node "power bi/pbip/build-pages.js"`; re-run it after changing page layouts, then open `olist dashboard pbip.pbip` and choose **Refresh**.

## Analysis conventions

- Delivery, cohort and seller analysis use purchases from 2017-01-01 to 2018-08-31 (`analysis_start_date` / `analysis_end_date` vars in `dbt_project.yml`); 2016 is sparse and later months are incomplete.
- An order is late when it is delivered on a calendar day after the estimated delivery date.
- Customers are counted by `customer_unique_id`. See `python/analytics/README.md` for the repeat-purchase and segmentation definitions.
- Regions and population come from the `brazil_states` seed (IBGE macro-regions, 2022 Census); run `dbt build` (or `dbt seed`) to load it.
- `freight_demand_elasticity` estimates how route order volume responds to weight-adjusted freight changes (about -0.5; observational, range roughly -0.1 to -1.0). `freight_subsidy_breakeven` compares freight share with the break-even line |elasticity| x commission; the commission rate is an assumption (`commission_rate` var, default 0.15).

## Configuration and data

- Copy `.env.example` to `.env` if setting up on another machine. `.env` contains local credentials and is ignored by Git.
- The raw CSVs are expected in `data/raw/`. They are ignored by Git and are not altered by the loader.
- dbt uses `olist_dw/profiles.yml`; it reads the same PostgreSQL environment variables as the loader.
